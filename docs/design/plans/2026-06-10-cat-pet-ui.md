# 硬件 UI 小猫宠物形象

日期：2026-06-10（最后更新：2026-06-13）
范围：在硬件屏幕上放一个会随对话状态动态变化的小猫宠物形象；先在 Web「真机模拟」页做出效果并验证状态映射，再移植到固件 LVGL。

## 目标与动机
- 让设备有「宠物感」：待机、聆听、思考、说话、出错等状态下小猫有不同表情/动作，儿童友好、状态可读性更强。
- 先用模拟器验证形象与「状态→表情」映射，不烧录即可迭代；定稿后再投入固件 LVGL 资源。

## 屏幕几何（与固件一致）
- 真机 LCD：ST7789，**240×284 竖屏**（见 `firmware/main/display_lcd.c` 的 `LCD_H_RES=240` / `LCD_V_RES=284`）。
- 模拟器展示区改为按此比例（240:284 竖屏）渲染一个「设备屏幕」镜像框，里面是小猫 + 大字状态 + 字幕，所见即真机所见的版式。

## 状态 → 表情/动作映射
以 `voice_ui_screen_t` / 模拟器 `sim.screen` 为驱动：

| 状态 | 小猫表现 |
|---|---|
| boot/wifi/cloud/provisioning | 睡眼/加载感，轻微摇摆（连接中） |
| idle（在线待机） | 平静，周期眨眼，尾巴慢摆，呼吸式起伏 |
| recording（聆听） | 耳朵竖起、眼睛睁大、外圈聆听脉冲环 |
| thinking（思考） | 抬头、歪头、上方「…」动画 |
| playback（说话） | 嘴巴开合循环（说话感），可后续按播放幅度联动 |
| ble_gateway | 蓝牙等待态（耳朵微动 + 提示色） |
| error | 「× ×」眼 + 轻微摇头 + 警示色背景 |

屏幕背景色随状态轻微变化，强化状态区分（呼应固件 `screen_color`）。

## 分期
- **A 期（模拟器，先做）**：SVG 小猫 + CSS 按 `data-state` 切换的关键帧动画 + JS 在 `simRender()` 同步状态；模拟器展示区改 240×284 竖屏镜像。零硬件即可看效果、调表情与节奏。
- **B 期（固件 LVGL，定稿后）**：在 `display_lcd.c` 用 LVGL 绘制小猫（矢量 lv_obj/arc/line 组合，或预生成精灵帧图存 flash），状态由现有 UI 事件队列驱动；评估 flash/PSRAM 占用与刷新不阻塞 I2S/WS。表情节奏沿用 A 期定稿参数。

## 验证
- A 期：`node --check` + `tests/test_web_console_assets.py` 断言新屏幕/小猫元素；人工在「真机模拟」页切状态看动画。
- B 期：真机屏幕实测帧率不影响音频采集/播放；host UI 状态机测试不变（小猫只是渲染层，不改状态语义）。

## 多形象与后台切换（2026-06-10 增补）
- 形象不止小猫：新增**卡通小公主**（皇冠 + 头发 + 裙子 + 蓝眼睛），与小猫共用同一套状态动画（跳动/眨眼/说话嘴动/思考/聆听环，复用同名 keyframes）。
- **后台切换**：形象选择保存到**后端运行态配置** `ui.character`（`princess` | `cat`），API `GET/PUT /api/settings/ui`，**默认 `princess`**。这是后端设置（非浏览器本地），后续可同样驱动真机固件。
- 模拟器：屏幕 `data-character` 控制显示哪一个（CSS `display:none` 切换）；控制台「形象」下拉读写后端配置。
- 颜色用 SVG **内联 fill/stroke**，避免 styles.css 缓存导致只剩黑色剪影；CSS 仅负责动画与布局。
- B 期固件移植时，形象资源同样按 `ui.character` 选择（LVGL 矢量或精灵图）。

## B 期落地：固件 LVGL 小公主 + 5 状态文字（2026-06-13）

把模拟器小公主移植到真机 LCD（ST7789 240×284），并把语音识别状态文字提醒收敛成用户要的 5 个。

### 形象：精灵图管线（栅格，高保真）
- 不在固件里手绘矢量（与模拟器不像），改用**离线渲染精灵图**：
  - `firmware/tools/gen_princess_sprites.py`：从 `web_console/index.html` 抽出 `<svg class="princess">`，用**无头 Chrome**（本机 `/Applications/Google Chrome.app`）渲染为透明 PNG，再用 Pillow 裁切到统一 bbox、转 LVGL `LV_COLOR_FORMAT_RGB565A8`（`w*h*2` 字节 RGB565 小端 + `w*h` 字节 A8，stride=`w*2`，已对 LVGL 9.5 源码核实布局）。
  - 产物 `firmware/main/princess_sprites.c/.h`：3 帧——`neutral`（睁眼闭嘴，基准）、`blink`（闭眼，眼 `scaleY≈0.1`）、`talk`（张嘴，嘴 `scaleY≈1.7`），复刻模拟器 `cat-blink` / `cat-mouth-talk` 关键帧。
  - 帧选少而精：眨眼/嘴动用整图换帧；**聆听环、思考点、底色、跳动**用 LVGL 叠加层/动画实现，省 flash。
- 重生成命令：`python firmware/tools/gen_princess_sprites.py`（依赖 Chrome + venv 的 Pillow）。

### 显示（`display_lcd.c`）
- 用 `lv_image`（小公主精灵）替换原圆形按钮，图本身可点击 → `voice_conversation_hw_toggle()`（点形象开关对话，与模拟器一致）。
- 一个 `lv_timer`（LVGL 任务内）驱动帧动画：所有「在线」态周期眨眼；`播放中` 时 neutral↔talk 交替做嘴动。
- 叠加层：`收听中` 显示脉冲聆听环；`识别中/生成中` 显示上方思考点 `…`；按状态切屏幕底色（呼应模拟器 `data-state` 渐变）。
- 大字状态文字改为 5 个（见下）。

### 状态文字（5 个）与状态机
映射（确认稿）：

| 文字 | screen | 触发 |
|---|---|---|
| 开启 | `IDLE` | 已连云待机/刚开启（点我说话） |
| 收听中 | `RECORDING` | `RECORDING_START` |
| 识别中 | `RECOGNIZING`（新增） | `RECORDING_END`→ASR |
| 生成中 | `THINKING` | `ASR_RESULT`/`LLM_START`/`LLM_DELTA` |
| 播放中 | `PLAYBACK` | `TTS_START` |

- 新增 `VOICE_UI_SCREEN_RECOGNIZING` 区分「识别中」与「生成中」（原 THINKING 二者混用）。
- **播放完回到收听中**：固件 `conversation.c` 的 `VOICE_CONV_EVENT_TTS_FINISHED` 已 `enter_listening()`（→ `RECORDING_START` → 收听中），本期保持不变即满足。

### B 期最终形态调整（2026-06-13 晚）
- **形象切回小猫**：真机最终用模拟器的小猫（`<svg class="cat">`），生成器 `firmware/tools/gen_cat_sprites.py` → `firmware/main/cat_sprites.c/.h`（`cat_neutral/blink/talk`，99×115，≈100KB）。小公主精灵与其生成器已删除（沿用同一套渲染管线）。
- **字幕显示双方文字**：`ui_state.c` 字幕加前缀——识别结果显示 `你：<ASR>`（保留到首个回复 token），回复流式显示 `我：<reply>`，播放期间保留，下次 `RECORDING_START` 清空。
- **左上角改中文状态**：原显示 `device_id` 的 `s_lbl_topbar` 改显示 `screen_style().status_cn`（启动中/收听中/识别中/生成中/播放中…），device_id 不再上屏。

## 备注
- 形象是**纯渲染层**，不引入新协议/对话状态，不改 `ui_state.c` 语义；只消费既有 screen 状态 + 后端 `ui.character` 配置。
- B 期新增 `RECOGNIZING` 仅为文字区分，不改协议、不改对话状态机。
