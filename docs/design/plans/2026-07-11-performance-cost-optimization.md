# AI 硬件性能、交互体验与模型成本优化计划

**最后修改：2026-07-12**

## 目标

在不改变“服务端权威 + ESP32-S3 瘦客户端”架构、不清理用户数据、不部署生产环境的前提下，完成一轮可验证的 P0 优化：缩短同步 I/O 与错误状态等待、消除可复用 TTS 调用、压缩 LLM 上下文，并建立能持续衡量延迟和费用的指标。

## 审计基线

- 自动化基线：`435 passed, 7 failed, 1 skipped`。5 个失败是既有固件静态切片断言，2 个来自工作区中“默认本地后端”改动与旧测试契约冲突。
- 当前用户会话：120 条 `turns.jsonl` 约 17 MB，其中 Base64 音频字段约 17.28M 字符；239 份历史备份使目录约 2.2 GB。
- LLM 用量文件：352 条事件，399,451 prompt Token、91,161 completion Token；平均 prompt 约 1,135 Token，P90 约 1,881 Token。
- 语音审计：286 次回复、16,476 字符、217 个唯一文本；按精确文本估算，可缓存重复字符 2,446 个（14.8%）。按 5 元/万字符刊例价，历史回复 TTS 理论费用约 8.24 元，可直接缓存节省约 1.22 元；这只是当前本地审计样本，不等同云账单。
- 固件：16 kHz/16-bit/20 ms 采音；播放队列约 1.024 s，首播预缓冲约 128 ms。采音路径目前仍可能在持锁状态同步等待 WebSocket 发送，本期只记录为下一阶段任务。

## 本期实施

### P0.1 会话音频 sidecar 化

- `ConversationStore.attach_tts_audio` 改为 SHA-256 内容寻址的 `.pcm` sidecar。
- JSONL 只保存安全相对路径、格式、采样率、字节数；公共 API 不返回音频载荷。
- 回放接口兼容历史 Base64 和 sidecar。
- 重写轮次时无损外置历史 Base64；先写音频与临时 JSONL，最后替换元数据。
- `list_recent_turns` 只解析尾部所需行，避免为 8/20 条上下文解析全部历史。

### P0.2 普通回复 TTS 缓存与状态修正

- 新增全局有界 TTS 缓存，身份包含 text/provider/resource/voice/sample-rate/encoding。
- 默认上限 256 条、64 MiB，写入后按最近访问时间淘汰；不自动清理既有用户备份。
- 场景/成语已有缓存保持原路径；普通、兜底、本地规则回复使用通用缓存。
- 音频准备完成后再发送 `tts_start`；`source=cache` 标识命中。
- `tts_start/tts_end` 与审计记录准备、发送和端到端延迟、字符数、缓存命中。

### P0.3 LLM 调用预算与观测

- 上下文默认最近 8 轮、总计 3200 字符；摘要 2 条、结构化记忆 2 条。
- Agent 只做一次结构化记忆检索；安全/时间/口算本地路由不预构建模型上下文。
- LLM 成功与失败事件记录 request_kind、status/error_code、latency_ms、prompt/completion 字符数。
- Token 聚合增加成功/失败、平均/P95 延迟、平均 prompt Token；控制台同步展示。
- Web 成本页继续允许按当前运行态模型手动调整价格，并明确估算口径。

### P0.4 可靠性与首屏缓存

- 运行态配置写入改为同目录临时文件 + 原子替换，并收紧到 `0600`。
- 带版本号的 Web 静态资源使用 immutable 缓存；HTML 与无版本资源保持 revalidate；同步 bump 资源版本。

### P0.5 成本口径、并发与滥用护栏

- ASR 对 PCM 按实际样本字节计算音频时长，分开记录采集墙钟、`audio_end -> final` 和总延迟；Opus 暂以采集墙钟作为保守口径。
- 新 ASR/TTS 事件带 `metrics_version=1`；聚合器跳过旧事件并显示跳过数，不再将缺字段历史记录当成 0 费用。
- 生字、成语、场景预热等非 WebSocket TTS 合成也记入供应商请求事件；失败请求的可能计费字符单独显示，不假定为 0。
- 通用 TTS 缓存身份补入 schema 版本、端点与账户的非敏感指纹，命中时校验元数据、字节数和 SHA-256；截断 PCM 不入缓存。
- `ConversationStore` 按规范化用户目录共享进程内可重入锁，防止 append 与全量 replace 互相覆盖；TTS sidecar 写入移到 worker thread 并与音频下发并行。
- 协议限制文本 2000 字符、调试行 1024 字符、单帧 64 KiB、单语音段最大 30 秒/2.88 MiB，超限终止本段 ASR 而不断开整条 WebSocket。
- Token 页拆分云供应商请求与本地路由；多模型时不再用一组单价伪造总成本，交互指标接口失败时显示“不可用”而不是 0。

### P0.6 语音识别、意图等待与错误恢复（2026-07-12）

- 火山双向流式 ASR 上行由 20 ms 小帧合并为官方建议的 200 ms PCM 包；尾包在 `finish` 前补发，减少 WebSocket/压缩调度开销并提高识别稳定性。
- ASR 热词从“仅当前 persona 场景领域词”扩展为“所有启用场景的进/退意图短语 + 当前场景领域词”，让首次说“学英语/讲个成语/这个字怎么写”时也能获得软偏置。
- 固件消费 `asr_partial`，录音时显示实时字幕、录音结束后显示识别进展；`asr_result` 同时刷新 thinking watchdog，避免 ASR 已成功但后续意图/模型阶段误超时。
- 空识别和 ASR/LLM/TTS 异常返回面向用户的可重试提示，技术细节仅放在 `detail` 和本地审计中；固件先恢复会话 FSM，再显示“请再说一次”，避免错误页被瞬时覆盖或状态卡死。
- VAD 尾静音从 240 ms 调整为 320 ms，降低自然停顿造成的半句截断；保留自适应噪声基底和 120 ms pre-roll，不修改音频 GPIO、codec 或历史数据。
- 本地运行态 ASR 端点切换到项目接入文档推荐的优化双向流式 `bigmodel_async`；服务端仍运行在本机，不部署 ECS。

## 实施结果（2026-07-12）

- 当前 120 轮、17 MB 活动 JSONL 上，尾部读取中位数约 19.1 ms，全量解析约 58.9 ms，常用最近轮次读取约 3.1 倍加速。
- 同一真实用户的上下文样本从 1126 字符降到 573 字符，减少 553 字符（49.1%）；该比例是字符级实测，不直接等同 Token/账单降幅。
- 352 条历史用量事件涉及 Doubao mini、DeepSeek V4 Flash/Pro 三个模型；控制台因此显示多模型不可用单价直接汇总。
- 历史 286 次回复中精确重复文本可覆盖 2446 个字符（14.8%）；按 5 元/万字符示例价约可避免 1.22 元重复 TTS，仅为历史样本推算。
- 最终验收：`pytest -q` 为 **485 passed, 1 skipped**；Node 语法与配网测试通过；固件 5 组 host C 测试全过；ESP-IDF 5.5.4 干净构建成功，app 3,572,480 字节、分区剩余 13%。
- P0.1–P0.5 验收时未烧录；P0.6 于 2026-07-12 已烧录本地真机并验证 `esp32-001 hardware_online=1`。全程未部署 ECS、未删除 2.2 GB 历史备份。

## 明确不在本期自动执行

- 不删除 2.2 GB 历史 `.bak`，只阻止新音频继续放大元数据；清理需用户确认。
- 不改生产/ECS；真机仅烧录连接本机局域网服务的开发固件。
- 不在没有真实录音集时调整 VAD 语音概率阈值。
- 不一次性引入 LLM SSE + 分句并发 TTS；先用新增指标确定 TTFB 收益与缓冲风险。
- 不在本次性能改动中重做管理端会话鉴权；其为上线前安全阻断项，需单独设计设备 token 迁移。

## 验收

1. 新增/更新的 Python 单测、Web 静态断言和 Node 语法检查通过；全量测试从基线 7 个陈旧静态断言失败收口为 485 passed / 1 skipped。
2. 100 条带音频轮次的活动 JSONL 不随 PCM 字节线性膨胀，回放 API 返回原始 PCM。
3. 同文本同语音配置第二次 TTS 不调用 provider；配置任一身份字段变化即 miss。
4. `tts_start` 排在合成/缓存读取完成后，且缓存命中在事件与审计中可见。
5. 长对话上下文不超过 3200 字符，最近 8 轮仍保留，相关记忆不重复检索。
6. Token 指标返回成功/失败、平均/P95 延迟和平均 prompt；控制台能渲染这些字段。
7. 固件 host C tests 保持通过；不触碰用户当前未提交的本地/云默认选择改动。
