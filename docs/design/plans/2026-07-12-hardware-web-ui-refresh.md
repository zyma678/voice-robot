# 硬件端与 Web 端 UI 全面优化方案

**最后修改：2026-07-12**

## 目标

在不改变现有业务功能、WebSocket 协议和用户数据的前提下，统一硬件屏幕与 Web 控制台的视觉语言，提高状态辨识、文字可读性、触控命中率和动画流畅度。服务仍只运行在本机，不部署 ECS。

## 设计方向

- 视觉语言：深色“极光”基调，主色为蓝紫，实时语音状态使用青色/绿色/橙色/红色语义色；浅色主题保持同一层级关系。
- 信息层级：状态 > 当前任务 > 内容 > 调试信息。常用操作突出，高级配置继续折叠。
- 动效：Web 仅使用 opacity/transform/box-shadow，常规过渡 160–220ms；遵循 `prefers-reduced-motion`。硬件复用已有 90ms LVGL 动画定时器，不新增高频任务。
- 性能：不引入 Web 图片、字体或 UI 框架；硬件不新增位图资源，仅用 LVGL 基础图元，避免继续挤压只剩 13% 的 app 分区。

## Web 端

1. 重做主题 token：三层表面、渐变主色、统一圆角/阴影/焦点环和状态色。
2. 品牌区加入图形标识，侧栏导航增加图标和分组感；桌面保持固定侧栏，平板/手机转为可横滑顶部导航。
3. 面板、统计卡、表格、表单和按钮统一悬浮/按压/聚焦反馈；滚动条和加载态统一。
4. 对话页增强消息气泡、实时状态 pill、输入栏层次和录音脉冲；保持日志和高级配置可折叠。
5. 移动端保证 44px 触控高度、安全区、单列布局和无横向溢出。

## 硬件端

1. 顶部状态从纯文字升级为状态胶囊：语义色圆点、边框和柔和脉冲，一眼区分收听/识别/生成/播放/错误。
2. 字幕放入底部独立卡片，空字幕时隐藏；提示文字与字幕分层，避免与角色嘴部重叠。
3. 状态变化时更新胶囊/字幕卡配色；动画沿用单一定时器，避免 UI 阻塞 I2S 或 WebSocket。
4. 保留整块角色点击区、右上角下拉设置手势、成语/描红覆盖层及当前触摸协议，不改 GPIO。

## 验收

- `node --check web_console/app.js` 和 Web 静态资产测试通过。
- 固件 UI host/static 测试通过，ESP-IDF 构建成功；不新增 GPIO 或大位图资源。
- 深/浅主题、桌面/平板/手机布局均保持可读；`prefers-reduced-motion` 可关闭非必要动效。
- 本地服务与历史数据不受影响，不部署 ECS。

## 实施结果

- Web 与固件 UI 已按方案落地；Web 未引入图片、字体或第三方 UI 框架，固件未增加 GPIO、位图或动画任务。
- 全量 Python 测试 `491 passed, 1 skipped`，Web UI/资产测试 54 项及固件 5 组 host 测试通过，前端 JavaScript 语法检查通过。
- ESP-IDF 构建产物为 3,573,840 B，app 分区剩余 13%；已烧录 `/dev/cu.usbmodemXXXX`，全部写入 Hash 校验通过，硬复位后 `esp32-001` 已重新连接本地服务。
- 未触碰 ECS，未删除历史会话、备份或设备连接记录。
