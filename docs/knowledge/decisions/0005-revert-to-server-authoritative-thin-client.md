# 0005. 回退端侧自治：回归服务端权威 + 硬件瘦客户端

- 状态：已接受
- 日期：2026-06-12
- Supersedes：`0003-on-device-autonomy-dual-plane.md`、`0004-on-device-memory-storage.md`
- 相关：计划 `docs/design/plans/2026-06-12-server-authoritative-thin-client.md`、PRD §十二（端侧自治，已弃用）、§11.13–11.16（对话模式 / 配网 / LVGL / 协议增量，保留）、ADR `0001`（ASR 失败不得断 `/ws`）、`0002`（全双工打断）

## 背景

ADR 0003/0004 落地了「硬件端侧自治」：固件以 C 复刻 ASR→LLM→TTS 三段式 + 端侧记忆（`vr_*` 11 个模块 + `vr_llm_ark` 直连火山 Ark + LittleFS 存储），**数据平面设备直连火山云**，服务端退化为不带音频的控制面（key 下发 / 记忆同步）。

产品方向调整后，端侧自治的核心代价（编排 + 记忆**两份实现**、固件里 3 个流式云客户端 + 端侧 LLM 调用 + flash 读写）不再值得：

- 硬件端职责收敛为**只做复杂交互与语音输入输出**（采音上行 / 放 TTS / UI / 配网）；模型调度与记忆管理回到服务端单一实现。
- 服务端后续**发布到字节云供外网访问**，所有数据存服务端——「设备独立于自建服务端」的诉求由「服务端公网可达」替代，不再需要设备直连火山。

关键事实：6/11 的 `vr_*` 自治模块虽编进 build、有 host 测试与模拟器演示，但**从未接入固件实时对话通路**——`conversation.c`/`ws_client.c` 始终把音频走 `/ws` 上行、收服务端 TTS。故本次回退是删除「在场但未接线」的自治代码，6/10 瘦客户端通路本就完整。

## 备选方案

- **A：维持端侧自治 + 双平面**（ADR 0003 现状）。优点：设备可独立于自建服务端。缺点：两份实现长期维护成本与漂移风险高；与「服务端发字节云外网访问」的新方向重复且更重。
- **B：回归服务端权威 + 瘦客户端**（本 ADR 选定）。设备只负责语音 I/O 与 UI，经 `/ws` 把音频上行、收 TTS；ASR/LLM/TTS/记忆/编排只在服务端一份实现；服务端发布字节云解决外网可达。
- **C：保留端侧代码但休眠不接线**。缺点：架构留双平面残留、易混淆，无收益。

## 决策

采用 **B：回归服务端权威 + 瘦客户端**，并锁定：

1. **硬删除固件端侧自治代码**：`vr_routing/retrieval/context/prompt/markdown/extract/paths/store/runtime/fs/llm_ark` 及其 host 测试；移除 LittleFS `storage` 分区与 cJSON/littlefs/http_client 等仅自治用的依赖。固件回归 6/10 瘦客户端形态（`conversation.c` + `ws_client.c` 经 `/ws` 走音频）。
2. **服务端为唯一权威**：ASR（火山 sauc）、LLM（Ark/Doubao）、TTS（seed-tts V3）、记忆（`memory/`）、编排（`agent/graph.py`）只在服务端实现；删除为端侧自治加的控制面支撑（`device_runtime.py`、`device_sync.py`、`push_keys`/`memory_sync`/`memory_report` 协议与端点、`/autonomous-turn`）。`agent/routing.py`（零行为变更抽取）保留。
3. **外网可达由服务端承担**：服务端后续发布到字节云供公网访问，固件 `ws_url` 指向公网入口；不再要求设备直连火山。
4. **配网保留**：BLE 配对 → web 设 WiFi（PRD §11.14 / 固件 `network_provisioning`）仍是瘦客户端形态的一部分，保留。
5. **开发模式不变**：先用 Web「真机模拟」跑通流畅闭环，最后烧录真机验收。

## 后果

- 正面：
  - 编排 + 记忆回到**单一 Python 实现**，消除双份漂移风险与固件 3 个流式云客户端的工程量。
  - 数据全部留服务端，便于统一管理、迁移与字节云部署。
  - 固件显著瘦身（去 LittleFS/cJSON/HTTP-TLS/Ark 客户端），flash/分区回归简单布局。
- 负面 / 代价：
  - 设备运行链路重新依赖服务端在线——由「服务端发布字节云、保证公网可达」缓解。
  - 6/11 端侧自治的 C 移植工作量作废（代码删除、文档弃用保留作历史）。
- 后续关注：
  - 服务端字节云部署与公网 `/ws` 可达性、鉴权、时延。
  - 瘦客户端在公网链路下的语音体验流畅度（ASR 流式首包、TTS 无缝播放）。
