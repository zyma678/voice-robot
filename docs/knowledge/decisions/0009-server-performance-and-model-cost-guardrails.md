# 0009. 服务端性能与模型成本护栏：音频 sidecar、TTS 缓存和上下文预算

- 状态：已接受
- 日期：2026-07-11
- 更新：2026-07-12（补充计量版本、资源上限与截断结果处理）
- 相关：PRD `docs/prd/esp32-s3-technical-solution.md` §11.17；计划 `docs/design/plans/2026-07-11-performance-cost-optimization.md`；ADR 0005（服务端权威瘦客户端）、ADR 0008（固定提示音缓存）

## 背景

2026-07-11 的真实运行数据审计发现：`xiaoming` 的 120 条当前对话记录因内嵌 PCM Base64 已达到约 17 MB，对话目录因每次全量重写都保留备份而达到约 2.2 GB；构建上下文需要同步解析这份文件。历史 286 次回复共 16,476 个字符，其中可由精确内容缓存复用的重复字符约占 14.8%。现有链路还在完整 TTS 缓冲开始前发送 `tts_start`，设备会提前显示“播放中”，但实际上仍在等待合成。

成本方面，当前代码默认模型 Doubao-Seed-2.0-mini 的公开刊例价远低于大模型 TTS：LLM 为 0.2 元/百万输入 Token、2 元/百万输出 Token；语音合成为 5 元/万字符，流式 ASR 为 4.5 元/小时。因此在短回复硬件对话中，重复 TTS 通常比压缩几十个 LLM Token 更值得优先治理。运行态可切换其他模型，价格不能硬编码为单一模型的真实账单。

## 备选方案

### 决策一：轮次语音存储

- 方案 A：继续 Base64 内嵌 JSONL。读取简单，但体积放大约 33%，任意附件更新都要解析和重写全部轮次，备份进一步倍增。
- 方案 B：每轮独立 PCM sidecar。JSONL 保持轻量，兼容现有回放接口；相同音频仍可能重复占用磁盘。
- 方案 C：内容寻址 sidecar。以音频摘要命名，同一用户的相同音频只保存一份；轮次只保存安全相对路径和元数据。

### 决策二：普通 TTS 成本

- 方案 A：所有动态回复每次现合成。行为最简单，但儿童重复提问、固定兜底和本地规则回复会重复计费并增加首音频延迟。
- 方案 B：按回复文本直接全局缓存。命中率高，但音色、资源版本或采样率变化时可能播放错误音频。
- 方案 C：按“文本 + provider/resource/voice/sample-rate/encoding”内容寻址，并设置条目数和总字节上限。

### 决策三：上下文与交互状态

- 方案 A：保留最近 20 轮和 6000 字符上限，在合成开始前发送 `tts_start`。信息最全，但 prompt、同步文件读取和错误状态等待均偏大。
- 方案 B：最近 8 轮 + 长期摘要/相关记忆，总预算 3200 字符；本地规则懒构建上下文；音频准备完成后才发送 `tts_start`。
- 方案 C：立即改为全流式 LLM SSE + 分句 TTS 并发。理论首字/首音频最优，但会同时改变 Agent、记忆提交、取消语义、TTS 平滑与固件缓冲，回归面过大。

## 决策

1. 轮次语音采用方案 C：内容寻址 PCM sidecar；读取兼容历史 Base64，写入时先落 sidecar，再原子更新 JSONL。
2. 普通回复 TTS 采用方案 C：建立有界、配置隔离的持久化缓存；已有场景/成语缓存继续保留。
3. 上下文与交互采用方案 B：最近 8 轮、3200 字符总预算、相关记忆复用同一次检索；`tts_start` 延后到音频真正可下发。
4. 本期先补齐阶段延迟、失败和缓存观测，再以数据决定是否进入方案 C（真正流式 LLM + 分句 TTS）。
5. ASR/TTS 计量仅接受带 `metrics_version=1` 且必需字段完整的新事件；历史事件显式计入 skipped，不补 0。
6. TTS 半句音频和 LLM `finish_reason=length` 均是降级/失败而非完整成功；不写通用缓存和长期回放。
7. 单语音段与协议文本必须有显式上限；对话存储的 append/rewrite 串行化下沉到 store，而重 I/O 放到 worker thread。

## 后果

- 正面：会话元数据从 MB 级回到 KB 级；上下文读取不再解析大块音频；重复回复可直接播放且不重复付 TTS 费用；设备播放状态与真实链路一致；成本页能看到调用质量而不只有 Token 总数。
- 负面 / 代价：首次安全迁移会产生 sidecar 与一次 JSONL 重写；缓存占用额外磁盘；最近 8 轮之外的信息依赖摘要和结构化记忆；全量流式首音频优化仍留待下一期。
- 后续关注：不得自动删除已有 2.2 GB 历史备份；需另行确认保留策略。固件采音任务同步阻塞、播放中单击打断、首启配网与管理接口鉴权属于独立 P0/P1，不在本 ADR 的代码改动范围内。
- 单进程存储锁已防止当前部署的丢轮次竞态；如未来开启多 worker/多主机，会话存储应迁移 SQLite/PostgreSQL 或加 OS 级文件锁。
- sidecar 引用感知回收暂不自动执行：旧 `.bak` 可能仍引用 PCM，在没有明确备份保留期之前删除会破坏回滚。
