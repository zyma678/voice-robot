# 0008. 意图场景框架：意图识别方式、场景作用域、提示音缓存

- 状态：已接受（2026-06-23 实现 P1/P2/P3）
- 日期：2026-06-23
- 相关：计划 `docs/design/plans/2026-06-23-english-learning-scene.md`；现有意图分流 `voice_robot/agent/routing.py`；人设 `bot_profile`（`runtime_config.py`/`admin_api.py`）；TTS 持久化缓存 `voice_robot/memory/vocab_explanation_store.py` / `idiom_explanation_store.py`

## 背景

要在聊天链路里识别用户「想学英语」的模糊口语指令，进入一个 Bot 人设为「少儿英语老师」的对话场景，并能通过语音退出；进出各有固定语音提示。要求架构可扩展以承载后续更多意图场景，且固定提示音需服务端持久化缓存以省 TTS Token。三处有取舍的决策需固化。

## 备选方案

### 决策一：意图识别方式

- 方案 A 纯关键词/正则：零 Token、确定性、与 `routing.py` 一致；但模糊表达覆盖弱，需不断补词。
- 方案 B 纯 LLM 分类：模糊覆盖最好；但每轮普通对话都付 Token + 延迟。
- 方案 C 关键词优先 + LLM 兜底：关键词命中即零成本进入；仅在关键词未中、但出现「弱学习信号」粗筛词时调一次轻量 LLM 分类。绝大多数普通对话不触发 LLM。

### 决策二：场景状态作用域

- 方案 A 单连接内存态：状态随 `/ws` 连接，断连/重启/换设备回通用对话。简单，契合「瘦客户端 + 服务端权威」（ADR 0005）。
- 方案 B 按用户持久化：跨会话记住场景；但要处理多设备、过期、重连恢复语义，复杂。

### 决策三：固定提示音处理

- 方案 A 每次现合成：实现最简；但固定短句反复合成纯浪费 Token。
- 方案 B 服务端持久化 PCM sidecar 缓存：复用 vocab/idiom 已验证模式；命中即零 Token，文案/音色/采样率变更自动重合成。

## 决策

1. **意图识别选方案 C（关键词优先 + LLM 兜底）**：进入判定先走 Web 可编辑的关键词表；未命中且含粗筛词（`英语/English/口语/speak/学/练` 等）才调一次受限输出的 LLM 分类。退出判定走纯关键词（指令明确，省成本、降误退）。进入场景后不再跑进入判定。
2. **场景状态选方案 A（单连接内存态）**：`current_scene` 存于 per-connection 作用域。
3. **提示音选方案 B（持久化 PCM sidecar 缓存）**：缓存 key = 文案 hash + voice_type + sample_rate + encoding。

## 后果

- 正面：普通对话零额外成本；模糊指令仍可被 LLM 兜底覆盖；提示音几乎零 Token；新增场景只加配置 + 默认人设，不改主链路；状态机简单无持久化心智负担。
- 负面 / 代价：关键词表需人工维护；LLM 兜底偶有误判（受粗筛词与提示词质量影响）；断连后场景丢失（符合瘦客户端预期，但用户重连需重新进入）。
- 后续关注：粗筛词与 LLM 兜底提示词需在 P3 调优并固化默认；按场景的 Token 用量纳入 `token_usage_store` 看板；若未来需要跨会话续场景，再评估升级为方案 B（按用户持久化）并新增 ADR。
